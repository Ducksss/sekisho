An API asks for payment. Sekisho checks the counterparty before the agent signs. A deterministic policy decides what happens next.

01 / SCREEN

Start with the evidence.

Wallet traits, a sanctions oracle, and a bounded source-of-funds trace build the picture of a counterparty.

02 / DECIDE

Let the policy decide.

Clear rules return ALLOW, HOLD, or BLOCK. Missing required screening data produces at least a hold. AI only explains.

03 / RECORD

Leave a verifiable trail.

Decisions and officer overrides are attested onchain through MultiBaas. Exact report bytes can be checked against their recorded hash.

Can I explore without API keys?

Yes. Clone the repository and run the console's fixture preview. It uses synthetic cases and browser-only simulations, with a visible fixture banner. Follow the quick start.

Is the live payment stack deployed?

Not yet. The components are implemented and locally tested. Live service configuration, testnet contract deployment, and the complete payment rehearsal remain pending. See the readiness checklist.

Does an ALLOW mean a wallet is safe?

No. It is a point-in-time decision under the configured demo policy, based on available evidence. Sekisho is not a certified AML programme or legal advice.

Where do payments happen?

The project's value-transfer and contract chain is Base Sepolia. Ethereum and Base mainnet are used read-only for screening. The public website makes no payments and does not connect to a wallet.
